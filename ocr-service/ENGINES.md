# موتورهای خوانش و لایهٔ تأیید

خوانش آفلاین فاکتوریزم روی یک سرویس پایتون محلی (`service.py`, پیش‌فرض
`127.0.0.1:8789`) انجام می‌شود. این سرویس **خودش** تصمیم می‌گیرد کدام موتور
بخواند؛ کاربر لازم نیست چیزی انتخاب کند.

## ترتیب انتخاب

| اولویت | شناسه | موتور | وضعیت |
|---|---|---|---|
| ۱ | `falcon-ocr` | Falcon-OCR (TII، ۲۷۰M پارامتر، Apache-2.0) | اگر وزن مدل در `models/falcon-ocr` و `torch`/`transformers` نصب باشد |
| ۲ | `ppocrv6-arabic` | تشخیص PP-OCRv6 + رکونایزر عربی PP-OCRv5 | اگر فایل ONNX تشخیص v6 در `models` باشد |
| ۳ | `ppocrv5-arabic` | تشخیص و شناسایی PP-OCRv5 (عربی) | همیشه در بسته هست |

سرویس هر موتور را در زمان راه‌اندازی می‌آزماید؛ هر موتوری که بارگذاری نشود
بی‌صدا کنار گذاشته می‌شود و پیامش در `GET /health` می‌آید. انتخاب دستی هم
ممکن است (فقط برای عیب‌یابی):

```bash
OCR_ENGINE=falcon   python service.py
OCR_ENGINE=ppocrv6  python service.py
OCR_ENGINE=auto     python service.py   # پیش‌فرض
```

### چرا «PP-OCRv6 + رکونایزر عربی»؟

خانوادهٔ PP-OCRv6 (PaddleOCR 3.7، سه اندازهٔ Tiny/Small/Medium) پنجاه زبان
لاتین و آسیای شرقی را پوشش می‌دهد و **عربی ندارد**. برای عربی/فارسی باید
رکونایزر چندزبانهٔ PP-OCRv5 (`arabic_PP-OCRv5_mobile_rec`) استفاده شود. پس
ترکیب درست این است: **تشخیص v6 (کادر دقیق‌تر روی رسید چروک) + شناسایی عربی
v5**. کد همین کار را می‌کند و هر وقت فایل ONNX تشخیص v6 در `models` گذاشته
شود، خودکار جای v5 را می‌گیرد.

### دربارهٔ Falcon-OCR-Arabic

TII نسخهٔ عربی را اکتبر ۲۰۲۶ معرفی کرد، اما تا این لحظه **وزن‌های قابل
دانلود آن منتشر نشده** و فقط دمو/playground دارد. وزن‌های مدل پایه
(`tiiuae/Falcon-OCR`، ۱٫۰۸ گیگابایت، Apache-2.0) در دسترس است و رابط رسمی:

```python
model = AutoModelForCausalLM.from_pretrained("tiiuae/Falcon-OCR", trust_remote_code=True)
texts = model.generate(image, category="table")   # جدول HTML
texts = model.generate(image, category="text")    # متن ساده
```

`falcon.py` همین رابط را صدا می‌زند و خروجی HTML/متنی را به جعبه‌های ساختگی
تبدیل می‌کند تا فهم جدول (`table.py`) بدون تغییر کار کند. چون `generate`
امتیاز توکن نمی‌دهد، سقف اطمینان این موتور محافظه‌کارانه **۰٫۸۲** است؛ یعنی
خروجی Falcon همیشه در وضعیت «بازبینی اختیاری» می‌ماند و خودکار تأیید نمی‌شود
(با `OCR_FALCON_TRUST=1` قابل تغییر — توصیه نمی‌شود).

دریافت وزن‌ها روی دستگاه متصل به اینترنت:

```bash
pip install huggingface_hub
python download_models.py --falcon                  # tiiuae/Falcon-OCR
python download_models.py --falcon --repo <repo>    # اگر نسخهٔ عربی منتشر شد
```

## لایهٔ تأیید (`validate.py`)

فلسفه: **مدل می‌خواند، پایتون تأیید می‌کند.** بدترین حالت، خوانش ظاهراً موفق
با عدد اشتباه است.

| اطمینان | وضعیت | رفتار |
|---|---|---|
| ≥ ۸۵٪ | `ok` | اقلام و مبالغ خودکار پر می‌شوند |
| ۷۰–۸۵٪ | `review` | نارنجی؛ «بازبینی اختیاری» پیشنهاد می‌شود |
| < ۷۰٪ | `unsafe` | اقلام و جمع‌ها خالی؛ پیام «قابل تأیید نیست» |

بررسی‌های عددی که همیشه اجرا می‌شوند:

- **ناسازگاری ردیف** (`item_mismatch`): تعداد × قیمت واحد − تخفیف ≠ مبلغ ردیف.
- **ناسازگاری جمع** (`arithmetic_mismatch`): جمع اقلام + مالیات − تخفیف ≠ جمع کل.
- **whitelist عدد**: فقط `0-9 . / -` مجاز است؛ ارقام فارسی/عربی به لاتین
  تبدیل و حرف‌های شبیه رقم (`O→0`, `B→8`, `S→5`) اصلاح می‌شوند.
- **تاریخ** (`invalid_date`): فقط ۱۳۹۰–۱۴۰۵ شمسی یا ۲۰۱۰–۲۰۲۶ میلادی.
- **شمارهٔ فاکتور** (`invalid_invoice_number`): ۴ تا ۲۴ نویسهٔ عدد/خط تیره.

هیچ عددی ساخته نمی‌شود: فیلد مشکوک `null` می‌شود و در `flags` گزارش می‌گردد.
در سمت برنامه، خروجی موتور پشتیبان مرورگری (Tesseract.js) با پرچم
`unverified_engine` می‌آید و هرگز «تأییدشده» علامت نمی‌خورد.

## کالیبراسیون پارامترها (فاز ۳)

```bash
python calibrate.py --dir samples/receipts --limit 8
```

شبکهٔ `thresh` × `box_thresh` × `limit_side_len` روی عکس‌های خودتان اجرا
می‌شود و ترکیبی که **بیشترین عدد مالی با بالاترین اطمینان** را می‌خواند
پیشنهاد می‌شود. نتیجه را در متغیرهای محیطی بگذارید:

```bash
OCR_DET_THRESH=0.30
OCR_DET_BOX_THRESH=0.50
OCR_DET_SIDE=1920
```

پیش‌فرض‌ها همان مقادیر آزمون‌شدهٔ نسخهٔ قبل است: `thresh=0.20`,
`box_thresh=0.40`, `side=1600`. در سنجش روی تصاویر مرجع
(`scripts/ocr-bench`)، بالا بردن این‌ها CER را کمی بدتر کرد (۴۹٫۳٪ → ۵۰٫۶٪)
و تعداد ردیف‌های کامل را بهتر نکرد؛ پس تغییر پیش‌فرض توجیه نداشت. عدد درست
را با `calibrate.py` روی رسیدهای خودتان پیدا کنید.

## درست کردن عکس (فاز ۵ — کوتاه)

- کاغذ صاف و بدون چروک، نور یکنواخت، بدون بازتاب مستقیم.
- کل سند در کادر؛ لبه‌ها بریده نشوند.
- دوربین موازی با کاغذ (کجی بیش از ۵ درجه رقم آخر را می‌بلعد).
- اگر تاریک است از فلاش استفاده نکنید؛ چراغ محیط را زیاد کنید.
